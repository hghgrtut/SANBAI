# Правила работы в репозитории SANBAITeam

## Git: индексация файлов (СТОП-ГЕЙТ перед завершением)

**ГЕЙТ.** Задача не считается выполненной, пока не выполнено **и не показано** следующее:

1. `git add` **явными путями** всех новых и изменённых файлов задачи (не `git add .` / `git add -A`).
2. Показан вывод проверки:
   `git ls-files --others --exclude-standard -- '*.kt' '*.xml' '*.kts' '*.toml'`
   и `git status --short -uno` — каждый новый мой файл должен иметь статус `A`.

**Порядок жёсткий: `git add` + проверка — это ПОСЛЕДНЕЕ действие перед итоговым сообщением.** Тесты, сборка и
любая другая верификация выполняются ДО этого и не заменяют индексацию. Запрещено отправлять итоговый ответ с
изменёнными файлами, если пункты 1–2 не выполнены в этом же ответе.

- Посторонние untracked-файлы из вывода (например, `.idea/*`) не добавлять, но явно отметить в итоге.
- Коммит **не** создавать без прямой просьбы пользователя. Только индексация.

## Конвенции кода

- UI-строки на русском, лежат в `res/values/strings.xml` соответствующего модуля.
- Действия экрана (то, что дёргается из UI) выносятся в отдельный интерфейс `<Screen>Actions` рядом с вьюмоделью
  (`internal interface TrainingDetailActions`). Вьюмодель экрана его имплементирует и помечает методы `override`.
  UI принимает этот интерфейс (`actions: <Screen>Actions`), а не отдельные колбэки и не саму вьюмодель;
  `@Composable <Screen>(viewModel)` — единственное место, где вьюмодель пробрасывается как `actions = viewModel`.
  Это касается и новых экранов, и существующих при их правке: в похожих местах интерфейс создаётся, а не дублируются
  колбэки.
- Инлайн-действия внутри карточек/списков — Material3 `TextButton`; uikit `Button` — только для основных CTA
  (полноширинные кнопки, кнопки в диалогах).
